# One new selected-source prototype build

12 November 2026. Follow-up to [the generic-library rebuild](PROTOTYPE_GENERIC_REBUILD.md).
This experiment assembles the **selected** BOOT, five modules, original host
continuation, generic libraries and VU programs in one new private producer tree.
It is not a complete prototype port, all-room/campaign result, public ISO-only
installer or promotion of a new normal-launch profile.

## Fresh personal-disc producers

The original prototype and USA retail discs are read again without modification.
Fresh original ELFs are written only in ignored output. The retail ELF and frozen
metadata supply SDK identity evidence, **not transplanted retail addresses**.
The separately labeled discovery copy changes 40 non-text section flags while
preserving every PT_LOAD byte; the original ELF remains the runtime input.

The new recompiler produces 9,794 discovery files. Fresh static SDK matching and
finite-domain consistency reproduce 103 selected bindings and 152 known-direct
checks. Ambiguous no-outgoing candidates stay unselected. This does not qualify
every SDK ABI or prove guest execution coverage.

Fresh original module-import uses and bounded code-backed pointer prefixes derive
12 direct and 21 indirect BOOT ranges. The prototype's own SNR2 metadata supplies
298 instruction relocations in original table order. No old selected address map
or seed CSV is a producer. New BOOT generation yields 9,827 files, byte-identical
to the prior qualified outputs when consulted **after** generation as an oracle.
The existing **one error and 1,450 warnings remain**, including the unresolved
translation diagnostic. No unknown opcode is stubbed or replaced with NOP.

All five selected modules are emitted from fresh disc bytes, namespaced and
registered again: 729 functions and 744 raw source/header files. Their previously
observed load bases and registration policies are **explicit qualification inputs**,
not freshly inferred universal bases. All raw generated files match the old
oracles; the five processes retain zero errors and 88 warnings. This is not
general relocation, CFG, signature, ownership or lifetime validation.

### A retained-host dependency that needed explicit treatment

The older link contains a **direct** McPort host registration object in addition
to a library wrapper. Their API policies differ: the direct host uses the module
API, while the archived wrapper uses the runtime API. Merely regenerating the
archive was therefore not enough to remove that retained host source dependency.
The earlier registration experiment's explicit retained-host boundary matters.

This recipe regenerates the effective direct-host module-API wrapper from fresh
metadata; its entire source matches that retained direct wrapper. It does not
copy the populated table or blindly substitute the archive's policy. This is
source/link ownership hygiene, not an asserted new game bug or cleanup fix.

## Original host sources and insertion-only diagnostics

The qualified original host main, IOP/controls continuation and helper sources
remain explicit source inputs, with reviewed include rebasing. They are not all
derived solely from the disc or already packaged as a public prototype installer.
Generated game functions are **not** copied from their old instrumented versions.

Original [source_inserts.py](source_inserts.py), revision
`3aac1292c7f0535548146cb41f3f502f8adc6181`, applies a bounded private insertion
profile to four freshly generated functions. Both exact input and full output
SHA-256 are mandatory, with explicit line endings. Eight invented-data tests
cover identity, bounds, duplicates, unsupported edits and encoding.

The private profile separates previously authored observer declarations/calls
from the old generated bodies. Only insertions are applied; no original line or
PC/word comment is removed or replaced. All four complete outputs equal their
previous instrumented versions. That is a text-production check, not a general
C++ semantic, read-only, ABI, noninterference or formal clean-room certificate.
The qualified original callbacks and private profile still need their own
provenance; no game body, populated profile or address map is published.

## Whole selected-source interpreter bootstrap

The first compile stops on a CMake PCH spelling error: quoted header names are
treated as missing paths relative to the project root. Its failed configuration
and log are retained. Include-search angle syntax fixes that configuration issue;
there is no guest-code edit or false passing relabel of the first build.

The corrected whole build compiles and links in the new tree, without old
prototype objects, snapshots or generated-game source in its input graph.
The bootstrap executable is
`6494fe13cc3a97a9aa32c8ea9cd67bdc7df5fbe613780fe10ad314de53c43e8b`.

This bootstrap deliberately has **no compiled VU programs**. An actual AOT1
request is refused with exit29 before input verification/runtime/UI, instead of
pretending to register callbacks. A separate declared450s AOT0 run exits0 after
453.766 seconds, with all nine requested original PNGs. Its actual original menu,
room, Gene and HUD are directly viewed; existing artifacts remain.

The run captures five fresh 16-KiB VU images privately. Their manifest precedes
the old-image oracle. All nine original files also equal the earlier AOT0
samples, but this is a different bootstrap experiment, not a timing/ISA or normal
effect comparison. Captures, images and generated code stay private except for
the explicitly reviewed screenshot selections.
