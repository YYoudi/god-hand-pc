# Reconstructing selected-module registration source

12 November 2026. Follow-up to [selected-module source replay](PROTOTYPE_MODULE_REPLAY.md).
The developer-tools goal remains active; this is a source-dependency step, not a
new debug feature or complete prototype setup release.

## No cached wrapper/table as a producer input

The original public [registration helper](module_registration.py) reads the
qualified generated table format and renders original generic host boilerplate.
It receives linked images and extent metadata from the previous proved fresh
module chain. Those inputs are hash-checked; the four modules are **not** claimed
to have been regenerated again in this increment.

The parser checks the declared half-open range, slot count and array declaration,
then every explicit sparse assignment. Index-to-address consistency, duplicate
slots and declaration-name membership are checked. Unsupported assignment shapes
are refused rather than silently skipped. Empty slots are not filled with guessed
aliases. These checks do not prove CFG, instruction coverage, function signatures,
ABI, callback identity or overlay ownership.

The four qualified module bases, namespace/log identifiers and registration-API
choices remain explicit profile inputs. One existing wrapper calls the runtime
API and three call the module-table API; that distinction is preserved, not
collapsed or selected by guessing retail addresses.

All eight reconstructed header/source files are recorded **before** opening the
old wrappers as a comparison oracle. They then equal the original files
byte-for-byte, including the 6,849 explicit sparse alias records and their order.
The prior original wrapper shape and semantics were consulted while writing our
generic template: this is not a formal clean-room claim or recovered game source.
No populated table, address map or game function is published.

## A preserved failure limitation

The generated code retains the existing base and code-identity guards, API calls,
active flag and half-open clear range. It deliberately does not add guessed frees,
rollback, ownership or cleanup behavior while calling the result unchanged.

An actual compiled invented-data test exercises both API variants, wrong base,
explicit negative control, hash refusal, sparse calls, remove/reinstall and
partial registration failure. With the second call refused, the first entry
remains installed and the active flag stays false; removal therefore does not
clear it. **Installation is not transactional.** This is a demonstrated limitation
of the preserved host algorithm in the stub test, not an observed native failure
or a cause established for the separate original memory warning.

Static inspection also shows that the frozen native caller ignores install's
returned boolean. No failure-safe fallback or production recovery is claimed.
The SHA backend in the invented test is a controlled stub, not cryptographic,
game, hardware or real-runtime validation. Its unused-runtime-parameter compiler
warning for the module variant is retained. An earlier misleading-indentation
warning in our invented fixture was corrected; the first log is preserved.
