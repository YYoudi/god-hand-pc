13 November 2026, Europe/Paris. Production and validation straddle midnight;
the underlying UTC receipts are dated 12 November. Source
`c209f0c48d1e3c36d2eca76a413786495fe282a6` adds the original GPL

This follows [the public host-source producer](PROTOTYPE_HOST_PRODUCER.md).
Its 67 values no longer need a hand-maintained populated parameter table as a

## Provenance, not newly discovered semantics

The policy was authored using the previously qualified private profile and
original prototype instructions, consulted privately. The new production CLI
does not execute the private authoring script or read the old populated table.
It reads the original prototype disc/ELF, public original host source, and exact
previously qualified native capture records. This is GPL continuation work with
disclosed source exposure, **not clean-room independent-engine work**.

The public policy contains hashes, bounded window sizes, operand/register kinds,
relative field selectors and original host/include roles. It contains no game
instruction words, populated addresses, raw symbol map, generated game body or
capture. A window fingerprint is not a complete function body or independent
proof of a real function entry, semantic role, ABI or lifetime. Those roles retain
their earlier, explicitly limited qualification and native observations.

## What the producer derives

The 67 values comprise 13 original host-policy/test constants, 14 previously
qualified entry locations, ten observed module bounds, ten signed/unsigned
operand fields, seven absolute-address constructions, three checked aliases and
ten original include paths. Numeric spelling and suffixes are retained exactly.

There are 31 aligned fingerprint windows: 27 of 32 bytes and four of 64 bytes.
Absent or ambiguous windows refuse. Operand extraction checks the selected
instruction forms/registers and uses a small closed no-clobber check between a
LUI and its selected low operand; unknown intervening forms refuse. One selected
encoded low operand is in a JR delay slot. Accepting that encoded data arithmetic
does **not** establish CFG reachability, return behavior or executed delay slots.
No guest instruction, readiness status, memory flag or function body is changed.

Five pinned original registration JSON/capture pairs supply the module bases.
Their hashes, complete captured headers, extents and original-disc module
identities are checked. The prior static-link/code comparisons remain the basis
of qualification; this stage does not independently repeat all relocations or
certify mutable data, variable bases, loader ownership or arbitrary lifetimes.
No retail address or module profile is used. Historical captures remain private.

Original host templates and reviewed IOP/F1 edits still use separately fetched
GPL runtime source `1646d8854e1c3e16e5ec9bb7aeddebe0fe0fa14a`. That source is
not vendored. Output identities are computed from the newly derived parameters
and qualified host templates: they are **not an independent oracle**. A separate
manifest precedes comparison against the actual previously tested host files.

## Actual replay and refusal controls

All 67 parameter values and all five output identity/EOL records agree exactly
with the old profile. The qualification prose and profile file identity are new;
the complete old and new JSON files are **not** claimed byte-identical.

The existing public source producer then consumes the **newly generated** profile.
Its five fresh private outputs are byte-identical to the actual host sources of
the unchanged native executable
`e677f789c9f51400ba054b5a72ab7807f363a5bd4c099ba10f5c2c07edcc8e34`.
This connects the derivation to the build, not merely a self-consistent manifest.
The [earlier normal menu/action observations and original screenshots](PROTOTYPE_WHOLE_INTERACTIVE.md)
remain earlier evidence; no new native run, screenshot, graphics fix or normal
profile adoption occurs here.

Twelve actual CLI commands have expected results. The profile stage checks
check-only, wrong ELF/disc/upstream, missing include root, unsafe session, wrong
observation, new production and stale-session refusal. The source consumer then
checks check-only, new production and stale-session refusal. Only the two named
production steps change output trees; all ten non-production trees stay unchanged.
New profile/source manifests are saved before their respective old-oracle reads.

The exact-source suite passes **485 tests, four Windows skips, 79.400 seconds**,
including 20 new invented-data controls. Synthetic tests contain no game/vendor
bytes or captures and do not execute the original program. All 45,676 retained
file identities match. Detailed source/output hashes, selector counts and actual
control outcomes are in the [aggregate record](docs/evidence/prototype-host-profile-2026-11-13.json).

The CLI requires private observation paths, not supplied numerical addresses:

```powershell
python prototype_host_profile_inputs.py --source <pinned-private-upstream> `
  --elf <original-prototype-elf> --disc <personal-prototype-disc> `
  --observations <private-observation-paths.json> `
  --adapter-root <public-adapter-directory> --module-root <private-module-directory> `
  --session <fresh-private-name> --check-only
```

Without `--check-only`, it writes only a fresh ignored
`.local/prototype-host-profile/sessions/<fresh-private-name>` directory. Portable
include-root changes produce different host text and need their own build/native
acceptance, not inherited acceptance from this replay. Never publish the generated
profile, populated selectors, captured modules, original discs or binary.
